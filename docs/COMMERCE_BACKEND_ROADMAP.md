# Единое коммерческое ядро

Три представления сайта должны использовать один каталог, одну корзину, один источник цен и один источник остатков. Витрины не должны независимо хранить коммерческие данные.

## Текущее состояние

- исходная система: MODX + miniShop2;
- в снимке присутствуют браузерные части msCDEK2, msPyooKassa, miniShop2 и личного кабинета SendIt;
- новый фронтенд: статический Next.js, каталог и корзина работают локально в браузере;
- оформление формирует заказ в WhatsApp, но ещё не записывает его в учётную систему;
- поле `remains` в исходном miniShop2 заполнено только у 3 из 23 товаров. У остальных опубликованных товаров значение `0`, поэтому выводить его как «нет в наличии» нельзя.

## Целевая схема

1. **Master data.** 1С или выбранная складская система является источником SKU, цены, доступного остатка и резерва.
2. **Commerce API.** Серверный слой нормализует данные 1С для витрины, резервирует остаток при создании заказа и не отдаёт секреты во фронтенд.
3. **Доставка.** CDEK API рассчитывает варианты по адресу, габаритам и весу; выбранный тариф сохраняется в заказе.
4. **Заказы.** Оформление создаёт заказ в miniShop2/CRM/1С, после чего пользователь получает номер и статус.
5. **Личный кабинет.** Показывает заказы, статусы и документы. Остатки отображаются на карточках товаров, не как персональные данные кабинета.
6. **Админка.** Управляет контентом, акциями и витринными настройками; цены и реальные остатки изменяются только в master-системе.
7. **Акции.** Правила имеют период действия, список SKU/категорий, приоритет и аудит изменений; итоговая цена подтверждается сервером.

## Контракт остатка

```ts
type Inventory = {
  sku: string;
  available: number;
  reserved: number;
  updatedAt: string;
  source: "1c" | "minishop2";
};
```

Витрина показывает точное количество только если `updatedAt` укладывается в согласованный интервал актуальности. При недоступности учёта используется нейтральный статус «Наличие подтверждается при оформлении», а не выдуманное число.

## Что требуется для подключения

- адрес и способ доступа к 1С/API, тестовая база и карта SKU;
- рабочие CDEK API credentials и юридические параметры отправителя;
- решение, остаётся ли MODX/miniShop2 серверным ядром или заменяется отдельным commerce API;
- правила резервирования, отмены, оплаты и акций;
- роли администраторов и требования к журналу действий.

Секреты хранятся в менеджере секретов/VPS environment и никогда не коммитятся в GitHub.
